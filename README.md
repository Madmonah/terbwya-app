# ترباوية — terbwya.com

منصة اكتشاف وطلب طعام من المطاعم في مصر، مبنية بـ Next.js 14 + Supabase.
مشروع مستقل بالكامل عن مضمونة (madmona) — قاعدة بيانات وكود منفصلين تمامًا،
مبني بالاستعانة بنفس نموذج بيانات المطاعم في مضمونة كمرجع فقط.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # وحط بيانات Supabase بتاعتك
npm run dev
```

## قاعدة البيانات

في مشروع Supabase جديد (Dashboard → SQL Editor أو عبر Supabase CLI)، شغّل الملفين
بالترتيب:

1. `supabase/migrations/0001_init.sql` — ينشئ الجداول:
   - `cuisine_categories` — تصنيفات المطبخ (13 فئة مطابقة لفئات مضمونة بالضبط)
   - `restaurant_owners` — أصحاب المطاعم
   - `restaurants` — المطاعم
   - `restaurant_photos` — صور إضافية
   - `menu_items` — عناصر المنيو
   - `menu_item_sizes` — أحجام/خيارات الصنف
   - `customers` — العملاء (اختياري)
   - `orders` / `order_items` — الطلبات

قاعدة البيانات فاضية دلوقتي من أي مطاعم (البيانات المستوردة من مضمونة اتشالت
بالكامل بناءً على طلب صاحب المنصة) — هيتم إضافة مطاعم ترباوية من الأول، مستقلة
تمامًا عن مضمونة.

2. `supabase/migrations/0003_owner_dashboard_and_auth.sql` — نظام تسجيل دخول
   أصحاب المطاعم (مبني على Supabase Auth) + RLS policies تسمح لكل صاحب مطعم
   بإدارة مطعمه/منيوه/طلباته بس + RPC functions لنشر المطعم وتحديث حالة الطلب.

## نظام تسجيل المطاعم (زي مضمونة بالظبط)

بالاستعانة بمعمارية مضمونة كمرجع (فورم تسجيل ذاتي + داشبورد لكل مطعم + تتبع
طلب برقم مرجعي)، ترباوية فيها دلوقتي نفس الفكرة لكن بكود مستقل بالكامل:

1. **تسجيل صاحب مطعم** (`/owner/signup`): يعمل حساب بالإيميل وكلمة السر
   (Supabase Auth) وبيانات نشاطه.
2. **فورم إضافة مطعم متعدد الخطوات** (`/join`): بيانات أساسية → الموقع →
   أصناف المنيو → مراجعة ونشر. المطعم بينشر فورًا (`published`) بعد آخر خطوة.
3. **داشبورد صاحب المطعم** (`/owner/dashboard/[id]`): KPIs (عدد الطلبات،
   طلبات قيد الانتظار، الإيراد)، إدارة كاملة للمنيو (إضافة/حذف/تفعيل-تعطيل)،
   وإدارة الطلبات (تحديث الحالة خطوة بخطوة: قيد الانتظار → مؤكد → بيتحضّر →
   في الطريق → اتسلّم، أو إلغاء).
4. **تتبع الطلب بالرقم المرجعي** (`/order/[reference]`): صفحة عامة للعميل
   يشوف فيها حالة طلبه لحظة بلحظة بعد ما يأكد الأوردر من `/cart`.

كل الصلاحيات محمية بـ Row Level Security على مستوى القاعدة (مش مجرد فحص في
الفرونت إند) — كل صاحب مطعم يقدر يدير مطعمه بس، والطلبات بتتقرأ/تتحدّث حسب
`is_restaurant_owner()` اللي بتتأكد من `auth.uid()`.

⚠️ ملحوظة: تأكيد الإيميل (`mailer_autoconfirm`) مفعّل افتراضيًا في إعدادات
Supabase Auth، يعني لما حد يسجّل حساب جديد كصاحب مطعم هيحتاج يأكد إيميله
الأول قبل ما يقدر يسجّل دخول وينشر مطعمه. لو عايز تشيل الخطوة دي (auto-confirm
فوري بدون إيميل)، ده بيتغيّر من Supabase Dashboard → Authentication → Providers
→ Email → "Confirm email" (يُطفى).


## الهوية البصرية

- الألوان: أحمر `#D62828` وبرتقالي `#F77F00` وأمبر `#FCBF49` على خلفية كريمية دافئة `#FFF8F0`
- الخط: Cairo (عربي/لاتيني)
- الاتجاه: RTL بالكامل

  `0003_owner_dashboard_and_auth.sql`)، فاضية حاليًا من أي مطاعم (بناءً على طلب
  صاحب المنصة — القاعدة جاهزة تستقبل مطاعم حقيقية من الصفر)
- **الهوية البصرية كاملة**: ألوان أحمر/برتقالي/أمبر دافئة، خط Cairo، RTL،
  ولوجو فعلي مصمم (طبق بخار + حرف "ت") مركّب في الهيدر والفيفيكون
- **نظام تسجيل المطاعم والداشبورد** (بمعمارية زي مضمونة: فورم تسجيل ذاتي +
  داشبورد لكل مطعم + تتبع طلب برقم مرجعي) — مبني بكود مستقل بالكامل واتاختبر
  end-to-end فعليًا (تسجيل حساب → إنشاء مطعم → إضافة صنف منيو → نشر → طلب
  من عميل ضيف → ظهور الطلب في داشبورد المالك → تحديث الحالة → ظهور التحديث
  في صفحة تتبع الطلب العامة)

محتاجين لسه:

1. إضافة مطاعم ترباوية حقيقية (القاعدة فاضية دلوقتي — أصحاب المطاعم يقدروا
   يسجلوا مطاعمهم بنفسهم من `/join` على terbwya.com)
2. قرار: تفعيل/تعطيل تأكيد الإيميل عند تسجيل صاحب مطعم جديد (شرح فوق)
3. ملحوظة: المشروع الجديد بتكلفة 10$/شهر إضافية على حسابك في Supabase (منفصلة عن مضمونة)
